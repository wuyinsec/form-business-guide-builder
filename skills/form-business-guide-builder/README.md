# 表单业务指引生成工具

该 Skill 用于把内控系统项目中零散的制度、表单截图、附件清单、需求文档、操作手册和实施说明，整理成每张表单的四个业务助手板块，并在人工审阅后生成可导入的 DAT 文件。

## 适用范围

本工具**仅适用于金政软件开发的内控系统 P1 版本的业务助手配置**。

- 不适用于其他厂商的内控、财务或报销系统；
- 不得默认用于金政软件其他产品或 P1 以外的系统版本；
- 使用前应确认项目系统名称和版本；
- 无法确认属于 P1 版本时，可参考本工具的资料整理方法，但不得直接使用其 DAT 生成结果；
- 即使项目属于 P1 版本，也应提供当前系统实际导出的 DAT 样例进行结构验证，避免项目定制或版本更新造成不兼容。

## 适合什么场景

- 新单位上线事前申请、报销或其他内控表单；
- 旧项目重新整理业务助手；
- 多份资料存在重复、冲突或缺项；
- 需要先用 Excel 审阅，再批量制作 DAT；
- 需要确保 DAT 与最终审阅文字逐项一致。

## 可以提供哪些资料

资料没有强制清单，有什么就提供什么。以下内容仅为建议：

- 表单截图或字段清单；
- 单位制度、报销指引；
- 单位确认的附件清单；
- 项目需求文档；
- 系统操作手册；
- 审批流程图；
- 历史业务助手；
- 系统导出的 DAT 样例；
- 实施人员掌握的特殊规则。

缺少部分资料时仍可先生成初稿。Skill 会把无法确认且可能影响正确性的内容列为待确认，不会自行补制度。

## 四个板块

1. **业务助手内容**：说明表单用途和适用范围。
2. **业务流程指引**：说明填单、送审和后续办理步骤。
3. **业务填报指引**：说明关键字段、系统联动、金额校验及易错点。
4. **附件清单说明**：区分必传、按条件上传、系统自动生成和后补材料。

详细规范见 `references/four-sections.md`。

## 推荐使用流程

### 第一步：整理初稿

示例请求：

> 使用 `$form-business-guide-builder`，根据我提供的资料整理各表单业务助手。附件规则以单位确认清单为准，资料未明确的内容不要自行补充，先生成审阅 Excel 和待确认事项。

Skill 会盘点已有资料、识别表单及项目规则、整理四板块文案、标注待确认事项，并生成审阅表。

### 第二步：人工审阅

实施人员或单位业务人员直接修改 Excel。Excel 前五列请保持为：

```text
表单名称 | 业务助手内容 | 业务流程指引 | 业务填报指引 | 附件清单说明
```

可在后面增加“待确认事项”“依据摘要”等辅助列。

### 第三步：生成 DAT

示例请求：

> 这份 Excel 已审阅确认，请使用 `$form-business-guide-builder` 按 Excel 原文生成 DAT，不再优化文字，并完成逐字段一致性校验。

也可手工运行：

```powershell
python scripts/xlsx_to_dat.py 审阅确认版.xlsx --template 系统导出样例.dat --output-dir DAT输出目录
python scripts/validate_dat.py DAT输出目录 --xlsx 审阅确认版.xlsx
```

## 重要注意事项

- 开始工作前先确认项目使用的是金政内控系统 P1 版本；不是或无法确认时，不生成 DAT。
- 默认不允许联网查找或补充规章制度。
- 不允许引用其他单位、其他项目或模型记忆中的规则。
- 金额、比例、人数、时限、审批条件和必传附件必须有当前项目依据。
- 资料未明确时，应使用中性表达或列为待确认，不能猜测。
- “必传”只有在资料明确或系统已验证为强制时才可使用。
- 资料冲突时按用户指定优先级处理；没有明确优先级时应提出待确认。
- 最终 DAT 只能来源于用户确认后的 Excel，转换时不得再次润色。
- 原始资料、原始 DAT 和旧版本输出应保留，新版本输出到独立目录。
- 不要把含真实单位账套、用户、组织或表单 ID 的 DAT 作为公共模板传播。

## 文件结构

```text
form-business-guide-builder/
├─ SKILL.md
├─ README.md
├─ agents/openai.yaml
├─ references/
├─ scripts/
└─ assets/
```

`SKILL.md` 是 Codex 执行入口；`README.md` 面向实施人员；`references` 保存资料边界、四板块及审校规范；`scripts` 提供确定性的 Office 提取、Excel→DAT 和校验能力。

`assets/review-records.example.json` 和 `assets/review-example.xlsx` 是不含真实项目数据的结构示例，可用于了解审阅表格式；正式项目应另存新文件，不要直接在公共示例上保存单位资料。

## 当前限制

- DOCX/XLSX 提取脚本读取正文和单元格文本，不代替人工查看复杂图片、批注或扫描页。
- 若系统 DAT 结构发生变化，应先导出一个新样例并重新验证。
- 表单截图中的动态联动和隐藏字段，仅靠静态截图可能无法完全确认，必要时应由实施人员补充实际操作说明。

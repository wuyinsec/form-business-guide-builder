# 表单业务指引生成工具

把当前项目已有资料整理为面向普通职工的简洁业务助手。资料可以不完整；先利用已有信息形成可审阅初稿，再把用户确认后的审阅表转换成 DAT。

## 适用范围

- 仅适用于**金政软件开发的内控系统 P1 版本**中的业务助手配置。
- 不适用于其他厂商系统，也不得默认用于金政软件其他产品或其他版本。
- 若用户未说明系统及版本，应先确认是否为金政内控系统 P1 版本；无法确认时，只能提供通用资料整理建议，不得生成或承诺可导入 DAT。
- P1 业务助手 DAT 使用本 Skill 内置的固定格式，正常情况下不要重复要求用户提供 DAT 样例。
- 生成 DAT 前必须让用户准确提供目标单位的 `accountSetId`（账套ID）；不得猜测、沿用其他项目或使用占位值。

## 不可突破的资料边界

- 仅使用当前项目资料、系统实际表现和用户明确确认的信息。
- 默认不联网检索制度，不引用其他单位、其他项目或模型记忆补充当前单位规则。
- 金额、比例、人数、时限、审批条件、必传附件等具体要求必须有当前项目依据。
- 资料未明确时使用中性表述，或列入待确认事项；不得自行推定。
- 资料冲突时遵循用户指定的优先级；未指定且无法判断时列为待确认。
- 从确认版 Excel 生成 DAT 时只做格式转换，不得再次改写业务内容。

开始资料整理前必须阅读 [资料边界与证据规则](references/source-boundary.md)。

## 四个板块

所有表单统一整理为以下四段，具体边界见 [四板块写作规范](references/four-sections.md)：

1. **业务助手内容**：这张表做什么、何时使用。
2. **业务流程指引**：填单后如何流转和完成后续业务。
3. **业务填报指引**：关键字段怎样填、哪些系统规则最容易出错。
4. **附件清单说明**：什么必传、什么按条件上传、什么自动生成或后补。

不得把同一内容机械重复到四个板块，也不得逐字段复述整张表单。

## 工作模式

### 整理初稿

1. 盘点用户已提供的文件、截图和口头说明，不要求资料齐全。
2. 识别表单清单、字段、系统行为、制度要求、附件条件和流程规则。
3. 内部记录每条具体规则的来源和确认状态，防止串表；该记录默认不要求用户填写。
4. 对每张表单编写四板块内容，并把高风险缺失项单独列为待确认事项。
5. 生成审阅 Excel。推荐列为：表单名称、四板块、待确认事项、依据摘要。
6. 按 [审校与交付流程](references/workflow-and-review.md) 完成用词、适用条件和资料一致性检查。

资料不完整时继续工作：能确认的写入初稿，能中性概括的谨慎概括，不能确认的放入待确认事项。不要为了让内容“完整”而创造规则。

### 从审阅表生成 DAT

只有用户明确表示 Excel 已审阅或要求生成 DAT 时才进入此模式。

1. 确认系统为金政内控系统 P1 版本，并取得用户提供的目标 `accountSetId`（账套ID）。账套ID是 DAT 能否导入的重要条件，缺失时停止生成并向用户索取。
2. 使用 `assets/p1-dat-template.json` 的固定结构；正常情况下不要求用户重复提供 DAT 样例。
3. 审阅表前五列须为：表单名称、业务助手内容、业务流程指引、业务填报指引、附件清单说明。
4. 运行 `scripts/xlsx_to_dat.py`，写入账套ID、表单名称和四个富文本字段。
5. 运行 `scripts/validate_dat.py`，验证数量、JSON、UTF-8、账套ID、四段非空及 Excel→DAT 逐字段一致性。
6. 输出到新目录，避免覆盖旧版文件；明确告诉用户最终采用的是哪一版 Excel。

如果用户反馈 DAT 无法导入，优先排查：`accountSetId` 是否属于目标账套、文件是否为无 BOM UTF-8 JSON、固定字段是否完整。只有固定格式仍不能导入时，才让用户提供目标环境导出的 DAT 样例用于结构差异比对；不要把样例设为日常必需资料。

命令和文件格式见 [DAT 格式与脚本](references/dat-format.md)。

## 建议资料，而非强制资料

可以建议用户提供：表单截图或字段清单、单位制度、报销指引、附件清单、需求文档、操作手册、流程图、历史业务助手，以及实施人员掌握的特殊规则。缺少其中任意一项都不应自动阻止初稿整理。

`accountSetId` 不影响初稿和审阅表整理，但它是生成最终 DAT 的必需信息。DAT 样例仅在导入失败或怀疑目标环境结构异常时再索取。

仅当继续执行会造成明显错误时才询问，例如无法识别表单名称，或两个同优先级资料对同一必传规则直接冲突。

## 交付要求

- 文案应让没有制度背景的普通职工一次读懂。
- “必传”必须有明确依据；不确定时写“按需上传”或列为待确认。
- 操作路径、自动带出、金额校验和条件显示等系统细节应优先写入填报指引。
- 最终 DAT 必须通过脚本校验；不能只凭人工抽查。
- 最终 DAT 的 `accountSetId` 必须与用户提供的目标账套ID一致。
- 如用户只要求初稿，不提前生成最终 DAT。
